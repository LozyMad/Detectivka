Первоначальный IP VPS Beget: 159.194.245.92. Имена: detektum.ru и www.detektum.ru.

Обновление около 18:37–18:40 МСК: пользователь назначил новый IP
159.194.252.192. HTTPS с принудительным новым адресом отвечает 200 для
обоих имён; TCP:443 и HTTP по IP доступны из трёх российских и двух
зарубежных точек. Публичный DNS и прямые запросы DNS-серверов REG.RU
пока возвращают старый IP. Переход доменов на новый адрес ещё не подтверждён.
Подробности и ссылки на проверки — в последнем дополнении к
[исследованию](RUSSIA_CONNECTIVITY_RESEARCH_2026-10-03.md).

## Подтверждённые результаты

- DNS A у Google и Cloudflare для обоих имён: 159.194.245.92.
- Конфигурация Nginx использует один HTTPS server-блок для обоих имён,
  proxy_pass http://127.0.0.1:3000 и действующий сертификат для обоих имён.
- Пользователь проверил HTTPS detektum.ru через 127.0.0.1 с правильным SNI:
  HTTP 200.
- Независимая проверка из GitHub после завершения перезапуска:
  https://detektum.ru/ и https://www.detektum.ru/ — HTTP 200;
  HTTP обоих имён — 301; HTTPS с принудительным IP — 200 для обоих имён.
  Время HTTPS-ответа около 0,44–0,47 секунды.
- Проверка из сети рабочего компьютера: www отвечает 200, основной домен
  даёт таймаут. Принудительный IP и исключение локального прокси не помогли.
  Принудительный TLS 1.2 тоже не помог основному домену; www ответил 200.
- Пользователь сообщил, что через мобильный интернет оба имени не открываются.

Независимый тест:
https://github.com/LozyMad/Detectivka/actions/runs/37128921311

В первом тесте были краткие ответы 502 во время параллельного деплоя.
Повторный тест с паузой после деплоя прошёл без ошибок. Эти 502 не объясняют
устойчивый таймаут основного домена из сети рабочего компьютера.

Результаты указывают на зависимость доступности от сети подключения.
Фильтрация трафика или проблема маршрутизации вероятны, но точная причина
и сторона ограничения пока не подтверждены. Nginx и DNS исправлять наугад
не требуется.

Beget описывает аналогичные избирательные сбои и просит данные для проверки:
