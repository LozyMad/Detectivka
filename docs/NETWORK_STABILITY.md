# Стабильность игры и доски расследования

Дата проверки: 2026-10-02. Изменения подготовлены в локальном проекте; на detektum.ru не развёрнуты.

## Что установлено

В прежнем клиенте состояние комнаты запрашивалось каждую секунду без ожидания завершения предыдущего запроса и без срока ожидания. Дополнительные интервалы дублировали опрос. При зависании сети запросы могли накапливаться. История и счётчик отдельно запрашивали один список поездок; затем клиент параллельно запрашивал выборы для посещённых адресов. У SSE не было heartbeat; таймеры повторного подключения не очищались при уходе со страницы. Быстрые перемещения стикеров запускали несколько сохранений, а поздняя ошибка могла откатить более новое положение.

Это подтверждённые проблемы кода, но причина недоступности сайта для всех устройств домашнего Wi-Fi пока не доказана. Успешный HEAD с компьютера проверял соединение в один момент, но не загрузку всей страницы на планшете. Отсутствие новой строки в access.log само по себе не доказывает отсутствие соединения: запись обычно появляется по завершении запроса. Таймаут `/events` в присланном журнале относится к потоку событий и не доказывает сбой загрузки главной страницы Safari.

## Исправления

- `frontend/js/game-network.js`: максимум 3 активных HTTP-запроса на страницу и 64 ожидающих; одинаковые GET объединяются с учётом заголовков авторизации. Срок ожидания API — 15 секунд, включая очередь и тело ответа; файлов приложений — 60 секунд. Запись имеет приоритет перед ожидающими чтениями. POST/PATCH/DELETE автоматически не повторяются.
- `frontend/js/game.js`: состояние комнаты опрашивается через 5 секунд после завершения предыдущего запроса; история — через 60 секунд. Ошибки увеличивают задержку до 60 секунд. Отсчёт времени работает локально по монотонным часам. История и счётчик используют один снимок, старый ответ не перезаписывает более новое изменение. Скрытая вкладка и offline останавливают фоновые чтения и SSE; возврат восстанавливает одну подписку. Закрытие предпросмотра отменяет загрузку файла.
- `backend/controllers/statsController.js`: ответы на выборы игрока PostgreSQL включаются в историю одним запросом БД с ограничением по авторизованному игроку и сценарию. Для старого сервера/SQLite или ошибки этого запроса сохранён резервный путь с двумя последовательными рабочими очередями вместо массового параллельного запуска.
- `backend/sse/roomEvents.js`: общий heartbeat каждые 25 секунд, удаление закрытых подписчиков и таймеров, отключение клиентов с заполненным выходным буфером, закрытие подписки при истечении JWT. Клиент отслеживает зависшее подключение и отсутствие heartbeat, закрывает старый поток перед повторным подключением и увеличивает задержку при ошибках.
- `frontend/js/investigation-board.js`: положение сохраняется последовательно; повторные перемещения одного стикера заменяют ожидающее положение последним. Ошибка старого сохранения не откатывает новое перемещение. Загрузка доски ждёт сохранений и не перезаписывает новые действия. Ошибка чтения не стирает доску. Двойная отправка формы блокируется.
- При неизвестном результате сохранения интерфейс сообщает, что операция могла уже сохраниться; повторная запись автоматически не отправляется. Ошибки HTTP без подтверждённой попытки не создают фиктивную поездку и не очищают введённый адрес. Последняя подтверждённая история сохраняется при сбое чтения.
- В `game.html` подключён новый сетевой модуль и обновлены версии скриптов для сброса браузерного кэша.
- Дополнение для админки: `authFetch` использует тот же сетевой модуль; опрос комнат не перекрывается, замедляется при сбоях и прекращается при уходе с вкладки комнат, скрытии страницы, offline и выходе. Последний список комнат сохраняется при ошибке. Начальная загрузка без авторизации не запускает запросы. Для загрузки папок приложений предусмотрен отдельный срок ожидания 120 секунд. Эти изменения ограничивают накопление административных запросов, но их связь с зависанием TLS не установлена.

Лимит действует на запросы этих игровых скриптов, а не на все вкладки, изображения и запросы браузера. Отмена HTTP не отменяет уже выполненную запись на сервере. Закрытие страницы до подтверждения сохранения требует проверки доски/истории после повторного открытия. Изменения не требуют миграции БД и не меняют сетевые настройки роутера.

## Проверки

Первоначальный прогон: 36/36 тестов прошли. Дополнение для админки добавляет проверки параллельных обновлений, двух страниц во время двухчасового моделируемого сбоя, жизненного цикла, сохранности данных, истечения сессии и медленной загрузки папки. Существующий тест жестов доски также проверяется отдельно.

После дополнения админки итоговый прогон: 43/43 теста прошли, тест жестов доски прошёл, синтаксис admin.js и git diff --check проверены.

Запуск (Node.js 18+):

```powershell
node --test scripts/test-network-stability.cjs scripts/test-game-stability.cjs scripts/test-board-stability.cjs scripts/test-server-stability.cjs scripts/test-admin-stability.cjs
node scripts/test-board-gestures.cjs
```

Если npm доступен, обе команды выполняет `npm run test:stability`.

Проверяются: 1000 одновременных обращений к чтению; ограничение очереди при обрыве; истечение срока ожидания во время получения тела; 1000 быстрых перемещений; отсутствие отката новым координатам; двойное сохранение формы; сохранность истории и адреса при ошибках; старые серверные ответы; скрытие/offline/возврат/BFCache; единственная подписка SSE; восстановление после обрыва; 5000 циклов подписки/отключения; истечение JWT; ограничение доступа к пакетным выборам. Реальный локальный HTTP-сервер проверяет JSON, 204, бинарный ответ и зависшее тело.

Двухчасовые сбои и простой SSE моделируются виртуальными часами; это не двухчасовой прогон на реальном Wi-Fi. Контракт PostgreSQL проверен с подменой запросов, без обращения к рабочей БД. Дополнительно в браузере на локальном стенде проверены создание стикера, связь, перемещение, повторная загрузка с сохранёнными координатами и размер экрана 768×1024; ошибок JavaScript не было. Этот браузерный прогон использовал тестовые API и Chromium, не Safari.

## Развёртывание и проверка на сервере

1. Сохранить текущую рабочую версию для отката. Перенести изменённые frontend/backend вместе, обязательно включая новый `frontend/js/game-network.js`. Не заменять `.env` или данные БД. Использовать обычный процесс развёртывания проекта; текущие локальные правки admin.html и style.css не входят в это исправление.
2. После обновления перезапустить известный процесс: `pm2 restart detectivka`. Это прерывает существующие SSE; клиент подключится снова. Во время активной игры выбрать подходящий момент для перезапуска.
3. Проверить `pm2 status`, `curl -I --max-time 10 http://127.0.0.1:3000/` и `curl -I --max-time 10 https://detektum.ru/js/game-network.js?v=1`. Новый файл должен отвечать 200. Повторно открыть вкладки игры, чтобы старый JavaScript не продолжал работать.
4. Проверить активную конфигурацию `sudo nginx -T` локально. Для SSE контроллер уже отправляет `X-Accel-Buffering: no`; убедиться, что nginx не игнорирует этот заголовок. `proxy_read_timeout` для потока должен быть больше интервала heartbeat 25 секунд; стандартное значение nginx — 60 секунд. Не увеличивать все таймауты до часов: это не устраняет накопление запросов. После реального изменения конфигурации выполнить `sudo nginx -t`, затем `sudo systemctl reload nginx` только при успешной проверке.
5. В тестовой комнате на том же Wi-Fi открыть игру на компьютере и Safari планшета. Проверить 30–60 минут перемещений стикеров, открытий приложений, переключений вкладок, сна/пробуждения и отключения/включения Wi-Fi. После повторного открытия сверить стикеры, связи и историю. Одновременно проверить главную страницу с другого устройства.
6. В консоли браузера на странице игры `window.gameNetwork.stats()` показывает активные, ожидающие и объединённые чтения. При простое ожидающих должно быть 0; активные HTTP не превышают 3, SSE учитывается отдельно. В Network один `/events` на видимую игровую вкладку; `ping` примерно раз в 25 секунд. После обрыва не должно быть непрерывной лавины повторов. На скрытой странице фоновая подписка закрывается.

Документация nginx: [proxy_read_timeout и управление буферизацией](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_read_timeout). Описание SSE: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events).

## Если Wi-Fi снова блокирует открытие

В момент сбоя выполнить на компьютере того же Wi-Fi полный GET, не только HEAD:

```powershell
curl.exe -v --connect-timeout 10 --max-time 20 -o NUL "https://detektum.ru/?wifi_check=stability"
Test-NetConnection 186.246.10.236 -Port 443
Resolve-DnsName detektum.ru -Type A
Resolve-DnsName detektum.ru -Type AAAA
```

Сохранить время сбоя и этап, на котором остановился curl: подключение, TLS, ожидание заголовков или тело. На сервере одновременно смотреть `sudo tail -n 0 -F /var/log/nginx/access.log /var/log/nginx/error.log`. Сравнить открытие того же URL через мобильную точку доступа. Журналы SSE содержат токен в query string: перед передачей удалить его.

Если полный GET на нескольких устройствах не проходит только в этой сети, дальнейшая проверка касается маршрута провайдера, роутера, IPv6/DNS и возможной фильтрации IP. Исправление игровых запросов снижает нагрузку и ограничивает последствия обрыва, но не доказывает устранение такой сетевой причины.

## Воспроизведение через «Организаторам» на iOS

Пользователь наблюдает зависание устройств в домашней сети после перехода с планшета на `/admin-login`, при этом сайт продолжает работать через мобильный интернет. Это не подтверждает полного падения сервера. Без сохранённой админской сессии переход отдаёт статический HTML и ресурсы, запрос входа выполняется только после отправки формы. Сохранённая сессия автоматически перенаправляет страницу на `/admin` и запускает административные запросы.

При проверке обнаружена отдельная ошибка: оба middleware проверки JWT использовали async callback без обработки отказа `User.findById`. Внешняя библиотека не перехватывает отказ возвращённого Promise, а обработчик `unhandledRejection` приложения завершает процесс. Отказ поиска пользователя теперь передаётся центральному обработчику Express и возвращает 500 для этого запроса. Это исправляет воспроизводимый отказ при ошибке БД, но его связь с зависанием домашней сети не установлена.

Восемь проверок аутентификации моделируют отказ и восстановление поиска пользователя, запрет доступа при неверном токене/удалённом пользователе и сохранение срока жизни SSE. До исправления четыре проверки отказа и восстановления падали; после исправления общий прогон прошёл 51/51. Для запуска включить также `scripts/test-auth-stability.cjs`; `npm run test:stability` уже включает его.

После обновления проекта на Ubuntu запустить перед воспроизведением:

```bash
bash scripts/diagnose-organizer-access.sh 2>&1 | tee /tmp/organizer-access.txt
```

Скрипт ничего не меняет и примерно 90 секунд проверяет локальные главную страницу, страницу входа напрямую через Node и HTTPS-страницу входа через nginx, сохраняя hostname/SNI и проверку сертификата. Версия проекта и `pm2 status` выводятся до и после. Во время сбора нажать «Организаторам» на планшете и проверить телефон через мобильный интернет. При 200 во всех локальных проверках и неизменном числе перезапусков PM2 искать ограничение домашнего IP/внешнего пути; при сбое только nginx — проверять nginx; при сбое Node — искать совпадающую ошибку/перезапуск приложения. Локальные успешные запросы не исключают зависание отдельных API.
