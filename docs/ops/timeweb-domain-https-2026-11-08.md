# HTTPS домена после переключения DNS

8 ноября 2026 исправлен завершающий этап подключения detektum.ru к Timeweb.
Оба A-адреса уже указывали на 179.236.41.171, но Nginx предлагал сертификат,
выписанный только на IP. Такой сертификат не подтверждает доменное имя;
ожидание обновления DNS или исключение в браузере это не исправляют.

## Действующая конфигурация

- `https://detektum.ru/` и `/admin-login` обслуживает приложение.
- HTTP обоих имён и `https://www.detektum.ru/` перенаправляются на основной HTTPS.
- Сертификат `detektum-domain` включает SAN detektum.ru и www.detektum.ru.
- HTTPS по IP сохранён для GitHub Actions. Его vhost отмечен `default_server`,
  поскольку клиенты при подключении по IP могут не отправлять SNI.
- Для IP оставлен noindex, для основного домена этот заголовок не добавляется.

Клиент: `/opt/detektum-certbot/bin/certbot`, конфигурация и сертификаты:
`/etc/letsencrypt-ip/`. Существующий `detektum-certbot-ip.timer` проверяет
продление всех сертификатов в этом каталоге. Dry-run доменного сертификата
и перезагрузка Nginx после продления проверены успешно.

Файл `deploy/timeweb/publish-domain.sh` воспроизводит настройку после того,
как DNS направлен на подготовленный сервер. Перед выполнением он сохраняет
старую конфигурацию и `.env` в закрытый каталог root на сервере. В Git
попадают только скрипт и описание; пароли, `.env` и приватные ключи не входят.

Проверены 200 для основной страницы и админки, 301 для HTTP и www, доверие
к обоим сертификатам и работоспособность прямого IP. База данных при этой
операции не изменялась; приложение для замены сертификата не перезапускалось.

GitHub Actions `Check site connectivity` проверяет актуальный IP Timeweb и
ожидает каноническое перенаправление www на основной домен.
