# Timeweb: полная адресная книга от 18 октября

`backend/data/addressBookBackup20261018.json` — точная сохранённая книга после
синхронизации с detektum.ru 18 октября 2026: **1093 записи**, все девять полей,
включая ID, примечания и даты. По указанию владельца сохранены также 14 строк
заголовков Excel и строка с названием «1»: очистка не выполняется.

Это снимок данных, а не обычный startup seed. Деплой кода не должен заново
перезаписывать книгу и отменять последующие изменения организатора.

Проверить точное совпадение действующей SQLite-базы:

```bash
python3 scripts/restore-address-book-backup.py --database backend/database.sqlite
```

Для явного восстановления именно этого снимка:

```bash
python3 scripts/restore-address-book-backup.py --database backend/database.sqlite --apply
```

Команда заменяет только адресную книгу, предварительно делает согласованный
полный SQLite-бэкап в `backups/address-book/`, проверяет неизменность других
таблиц и откатывает транзакцию при ошибке. Если другие таблицы ссылаются на ID
книги, автоматическая замена блокируется. Файлы SQLite, `.env`, пароли и
пользовательские базы в Git не добавляются.

На 7 ноября восстановление уже выполнено на Timeweb. Проверены все 1093 записи
через API всех 14 категорий и совпадение всех девяти полей в базе.

## Деплой

GitHub Actions `Deploy to Timeweb` обращается к
`https://179.236.41.171/api/deploy` с отдельным секретом
`TIMEWEB_DEPLOY_SECRET`. На сервере тот же секрет задан как `DEPLOY_SECRET`.
Это позволяет деплоить до переключения DNS и не отправляет запросы на Beget.

Приложение: `/home/detectum/apps/Detectivka`, пользователь `detectum`, PM2
`detectivka`, systemd `pm2-detectum`. Актуальный HTTPS по IP настроен с
автоматическим продлением. REG.RU и перенос старых сценариев — отдельные шаги.
