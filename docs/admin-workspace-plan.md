# Локальная переработка административного интерфейса

## Цель и границы

Сделать повседневные действия организатора и редактора понятными в визуальном стиле действующего Детектума. Работа выполняется локально: без пуша, деплоя и изменения данных detektum.ru. Исходные локальные данные также сохраняются; рабочий сервер использует отдельную копию базы и загрузок.

## Что обнаружено

- Одно меню смешивает обслуживание текущих игр, редактуру дел, обращения и служебные настройки.
- Раздел сценариев содержит создание, копирование, список, все адреса и интернет-страницы подряд.
- Формы создания занимают первый экран, вытесняя существующие комнаты и сценарии.
- Проверка самостоятельных игр вынесена на отдельную страницу, а ответы старых команд находятся в другом разделе. У них разные правила проверки; механически объединять данные нельзя.
- Организаторы и игроки — разные сущности с разной авторизацией. Их нельзя объединять в один список «Пользователи».
- Общая адресная книга — справочник города, а адреса сценария — игровые сцены. Их нужно отчётливо различать.

## Предлагаемая структура

1. Обзор: переходы к главным задачам и текущие комнаты без выдуманных показателей.
2. Проведение игр: комнаты, игроки и прохождения, проверка результатов, ответы отдельных команд, статистика.
3. Подготовка дел: сценарии с рабочими вкладками «Список дел / Сцены и приложения / Интернет-страницы», отдельная городская адресная книга, импорт и экспорт.
4. Администрирование: обращения с сайта, учётные записи организаторов, права доступа. Опасные операции — отдельная явно обозначенная область, вне списка сценариев.

В каждом разделе: понятный заголовок и пояснение, устойчивый адрес страницы, активный пункт меню, доступные действия. Создание и копирование открываются по кнопке, списки остаются главным содержимым. Внутренние вкладки не уничтожают DOM и черновики.

## Визуальная система

Тёплый почти чёрный фон, коричневые поверхности, светлый текст, медный акцент и Manrope из действующего кабинета. Компактные, читаемые таблицы; единые поля, статусы, кнопки и модальные окна. Без игровой декоративности, мешающей работе. Боковое меню с группами; на телефоне — выдвижная навигация, таблицы прокручиваются внутри контейнеров.

## Проверка идеи на противоречия

- Сохраняются ID форм и полей, существующие обработчики и серверные контракты.
- Навигация не создаёт комнаты, не запускает таймеры, не сохраняет формы и не меняет активный сценарий сама по себе.
- Права супер-администратора и организатора остаются прежними. Новые переходы также проверяют доступность раздела.
- Проверка общих игр и ответы отдельных команд доступны рядом, но их формулы и сохранение не смешиваются.
- Выбор дела для сцен и интернет-страниц остаётся явным: скрытая смена сценария могла бы сохранить изменения не туда.
- Скрытая форма должна раскрываться при переходе к ней из другой части админки и при ошибке валидации.
- Старые ссылки, включая `#player-management` и отдельную страницу проверки, должны продолжать работать.
- Поля и модальные окна не клонируются: иначе обработчики могли бы читать скрытый дубликат.
- Состояние загрузки и сетевые ошибки показываются честно; локальная копия явно обозначена.

## Последовательность

1. Зафиксировать исходную структуру DOM, права и набор проверок.
2. Подготовить изолированный localhost с рабочим сервером и копией данных.
3. Ввести общую оболочку, навигацию и визуальные токены.
4. Разложить существующие формы по рабочим вкладкам, сохранить обработчики.
5. Объединить входы в проверку результатов в одной навигации, сохранить самостоятельную страницу.
6. Проверить каждую группу функций в настоящем браузере, включая создание/редактирование на локальной копии, добавление времени, приложения, вопросы, экспорт и роли.
7. Выполнить существующие тесты стабильности и необходимые регрессии навигации. Исправить ошибки, проверить desktop/mobile, сохранить скриншоты.
8. Оставить локальный сервер запущенным и открыть готовую админку пользователю.

## Критерии готовности

Все прежние функции доступны; понятна разница между игроками и организаторами, сценами и адресной книгой, двумя видами проверки. Нет новых прав или изменений игровых правил. Черновики не теряются при переключении рабочих вкладок. Существующие тесты проходят. Локальная версия открывается по переданной ссылке; публикация не выполнялась.

## Выполнено и проверено

- Введены рабочий стол, группы навигации, поиск разделов, адреса разделов с поддержкой перезагрузки и истории браузера.
- Списки вынесены перед формами создания. Сценарии, сцены и интернет-страницы разделены вкладками. Настройки сценария и приложения также получили собственные вкладки без клонирования полей.
- Проверка общих комнат встроена в административную оболочку с прежними обработчиками. Ответы отдельных команд сохранены отдельно.
- Сохранены все 195 исходных ID и состав полей всех 16 исходных форм; повторяющихся ID нет.
- В браузере на изолированной копии созданы комната и черновик сценария; проверены запуск, пауза, увеличение времени, создание сцен, сохранение описания и вопроса, просмотр приложений и брифинга, загрузка полного ZIP-пакета, список игроков, быстрый поиск и переходы назад/вперёд.
- Для обычного организатора подтверждены прежние ограничения меню и невозможность открыть служебные операции прямой ссылкой.

- Исправлена обнаруженная ошибка обновления списка после добавления сцены; выбранный сценарий сохраняется при обновлении списков. Добавлены две регрессии. Полный набор: 191 тест прошёл, отдельно прошли проверки жестов доски.
- Опасные операции не выполнялись; отправка писем и изменения detektum.ru не выполнялись. Публикация результатов и удаление данных сохраняют существующие серверные обработчики и ограничения.

## Локальный запуск

Из корня проекта: `node scripts/start-local-admin.cjs`. Адрес: `http://127.0.0.1:3002/admin`.

Скрипт использует отдельные базу, сценарии и загрузки в `output/admin-local`, слушает только 127.0.0.1 и подключает текущие исходники frontend. Данные этой копии сохраняются между запусками. Повторный запуск требует остановить предыдущий процесс; существующий порт проверяется до подготовки файлов. Учётные данные локальной копии выводятся при запуске.

Исходная локальная база и production не изменены. Тестовые комната и сценарий оставлены в копии для просмотра. Скриншоты и протокол тестов находятся в `output/admin-workspace/` и `output/admin-workspace-tests-final.log`.

Уточнение по просмотру: группа «Администрирование» теперь раскрыта изначально; добавлен явный индикатор «−/+». Ранее заголовок выглядел статичным из-за скрытого стандартного маркера summary. Проверен переход к списку организаторов.
