- Проверка полного набора вопросов, типов, диапазонов, уникальности элементов и соответствия оценки сумме весов. Сервер сам вычисляет итоговую сумму и гонорар. Оценки вне рубрики не публикуются.
- Пустой бланк оценивается в ноль локально без платного запроса. Любой отдельный пустой ответ получает ноль независимо от вывода модели.
- При сомнении модели оценки остаются черновиком организатора. При технической ошибке сохраняется ручная проверка. Организатор может изменить результат; ИИ не перезаписывает его правки, даже если они сделаны во время запроса.
- Игрок видит сообщение об автоматической проверке и кнопку обновления результата. После завершения — обычные оценки и гонорар. Проверка демо не добавляет баллы общего рейтинга.

В вопросе о месте часов имя залогодателя больше не требуется: точное место оценивается в 3 балла вместо 2, общий максимум остаётся 5. Перебор взаимоисключающих мест не получает баллы за точное место.

Проверяются фамилия и роль поджигателя, расплывчатые ответы, независимые баллы за мотив, начальник Томаша и переставленные роли. Отчёт — `output/ai-identities-check.json`.

ИИ применяется к новым комнатам товара `borrowed-time` и к новым общим комнатам без таймера, созданным из админки с исходным сценарием этого товара. Функция должна быть включена, а семь исходных вопросов — сохранены. Старые комнаты и остальные сценарии не переводятся на новую проверку.

В админке при создании обычной комнаты доступен флажок «Без таймера». Такая комната ожидает ручного старта, после него вопросы доступны сразу. Пауза и продолжение сохраняются; завершает игру организатор. В списке отображается «Без таймера», добавление минут скрыто. Это отдельная настройка от тестовой комнаты. Новые комнаты с таймером сохраняют прежнее поведение.

Это исключает незаметную подмену пользовательской шкалы встроенной рубрикой. Для поддержки новых формулировок или новой шкалы нужно обновить `backend/services/borrowedTimeGrading.js` и повысить `VERSION`.

Для шестого вопроса поддерживаются широкая формулировка со скриншота и исходная формулировка «в автомастерской»; соответствующий пятый элемент шкалы выбирается при создании комнаты. Для седьмого не требуются сведения о растворителе, сделке и финансовом положении, которые пока не раскрыты в найденных материалах. Подробная методика — `answers-and-grading.md` в этой папке.

## От отправки ответов к гонорару

В общей комнате кнопка «Отправить ответы и получить гонорар» запрашивает подтверждение окончания игры. Бланк, завершение комнаты и постановка проверки в очередь записываются одной транзакцией. При конфликте правок бланк не отправляется и игра продолжается. Старые клиенты могут по-прежнему отправлять бланк без немедленного завершения.

После подтверждения игроки попадают на `/room-result`. Пока работает ИИ, экран обновляется автоматически. После публикации он показывает гонорар, баллы и число поездок, затем каждый вопрос: ответ команды слева, сохранённый эталон справа и оценку рядом с вопросом. Комментарий к оценке игроку не отображается. На телефоне колонки идут друг под другом. Такой же разбор доступен в истории кабинета.

Гости команды читают только результат своей завершённой комнаты через `/api/game/shared/result`, по уже выданному токену комнаты. Этот доступ не открывает завершённую игру заново. До завершения экран результата и эталоны недоступны. Эталоны берутся из сохранённой рубрики, а не генерируются при просмотре результата. При ручной проверке или ошибке ИИ экран показывает ожидание организатора, без выдуманных оценок.

1. Открыть `backend/.env.ai`. Для этого чата уже создан файл с пустым ключом; он исключён из Git. На другом сервере скопировать `backend/.env.ai.example` в `backend/.env.ai`.

3. Пока оставить `AI_GRADING_ENABLED=0`.
4. Запустить из корня проекта `node scripts/check-ai-grading.cjs` (или `npm run check:ai-grading`, если установлен npm). Команда выполнит три небольших реальных платных запроса к Яндексу, без изменения базы. Ожидаются `passed:true` для оценок 5, 3 и 0. Ключ, текст ответов команды и полные ошибки провайдера не печатаются.
5. После успешной проверки изменить `AI_GRADING_ENABLED=1` и перезапустить сервер. Сначала проверить новые тестовые прохождения демо с заранее оценёнными бланками всех семи вопросов.

Итоговые настройки:

```dotenv
AI_GRADING_ENABLED=1
YANDEX_AI_API_KEY=<секретное значение, вставить самостоятельно>
YANDEX_AI_FOLDER_ID=b1gvih69o63hf3q9qj04
YANDEX_AI_MODEL=deepseek-v4.1-flash/latest
```

`backend/server.js` читает сначала `backend/.env`, затем `backend/.env.ai`. Уже существующие переменные окружения имеют приоритет. Не задавать конфликтующие значения этих четырёх переменных сразу в нескольких местах.

Локальный файл на компьютере не настраивает опубликованный сайт: код и настройки должны оказаться на сервере, где работает сайт. Перенос ключа и запуск функции в продакшене выполняются отдельно. Создание локальных файлов в этом чате не означает публикацию изменений.

При запуске через предоставленный PM2-конфиг перезапуск из корня проекта: `pm2 restart deploy/beget/ecosystem.config.cjs --update-env`. Если используется другой хостинг, выполнить его обычный перезапуск приложения.

## Диагностика

- `AI_CONFIG_INVALID`: отсутствует ключ или некорректны настройки. Проверить секретное значение и файл окружения. Приложение не запускается при явно включённой, но неполной настройке.
- `AI_HTTP_401` / `AI_HTTP_403`: проверить ключ, срок действия, роли сервисного аккаунта и доступ к нужному каталогу. Playground работает с пользовательской сессией; его успех не доказывает работоспособность сервисного ключа.
- `AI_HTTP_400` / `AI_HTTP_404`: сверить URI и параметры с текущим примером «Код запроса» в карточке модели.
- `AI_HTTP_429`: лимит запросов или квота; до трёх попыток, затем организатор проверяет вручную.
- `AI_NETWORK_ERROR` / `AI_HTTP_5xx`: сеть, таймаут или сбой провайдера; тот же ограниченный повтор.
- `AI_INVALID_*` / `AI_GRADE_SUM_MISMATCH`: модель вернула некорректную структуру; оценки не публикуются.
- `AI_MODEL_CHANGED`: URI в настройках отличается от URI сохранённого задания. Такое задание отправляется на ручную проверку, чтобы не менять модель незаметно.

Внутренние подробности задания доступны организатору в API карточки проверки, включая модель, версию рубрики, попытки и безопасный код ошибки. Интерфейс организатора продолжает показывать обычные оценки и комментарии; повод для ручной проверки добавляется в комментарий соответствующего вопроса.
